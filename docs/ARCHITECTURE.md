# 系统架构说明

## 1. 设计目标

AgriRow Vision 的目标是把农机视觉感知、偏移估计和控制交互组织为可部署在车载工控机上的桌面客户端。系统采用模块化设计：视觉处理负责生成可解释的偏移信息，通信模块负责连接边缘端服务，界面层负责状态展示和人工控制。

## 2. 总体架构

```text
│                │                 │                   │
│ 摄像头/视频流  │ 消息序列化      │ 实时画面          │
│ 相机去畸变     │ 参数读写        │ 偏移曲线          │
│ 鸟瞰变换       │ 指令客户端      │ 参数配置          │

   相机/视频文件       边缘视觉服务          操作人员
                              │

```

## 3. 模块职责

| 模块 | 目录或文件 | 主要职责 |
| --- | --- | --- |
| 应用入口 | `App.py` | 初始化 PyQt5 应用并启动单页原型 |
| 检测演示 | `CropOffset.py`, `YOLO/` | 加载 YOLO 模型、显示检测结果、绘制偏移曲线 |
| 鸟瞰变换 | `ortho_record/` | 相机去畸变、单应性变换、视频采集与记录 |
| 通信客户端 | `clientside/` | 消息封装、指令发送、视频与预测结果接收 |
| 服务层 | `service/` | 日志、时间与基础网络服务 |
| 界面层 | `ui/`, `demo_onePageui2.py` | 监控、参数配置、状态显示与控制交互 |
| 设计资料 | `design/` | 数据流图、界面原型及 Draw.io 源文件 |

## 4. 视觉处理链路

1. 从本地摄像头、视频文件或远端边缘设备读取图像。
2. 根据相机内参和畸变系数进行去畸变处理。
3. 根据相机高度、俯仰角和视场角计算单应性矩阵，将图像转换为鸟瞰视角。
4. 使用检测模型生成目标框和可视化结果。
5. 计算检测目标中心与图像中心的横向距离，作为像素级偏移估计。
6. 在界面中显示当前偏移和历史曲线，并为后续控制策略提供输入。

当前 `CropOffset.py` 使用检测框中心均值估算偏移。这适合验证界面与数据链路，但尚不能等同于经过田间标定的作物行几何中心。用于真实控制前，应结合行结构拟合、相机标定和像素—物理距离映射进行改进。

## 5. 通信设计

系统将通信划分为两个通道：

- 指令通道：发送参数同步、模型启停、模型切换、系统切换和 PLC 控制指令。
- 视频通道：持续接收边缘端输出的图像及预测信息，并通过 Qt 信号更新界面。

消息对象在 `clientside/message.py` 中定义，系统类型、消息类型和响应类型在 `clientside/system_enum.py` 中维护。当前协议基于 TCP Socket，适用于局域网原型验证。

## 6. 部署边界

公开仓库仅包含桌面客户端和部分视觉原型。一次完整联机运行还需要：

- 与消息格式兼容的边缘端视觉服务；
- 根据目标作物训练并转换的模型；
- 经标定的相机内外参；
- 与 PLC 设备匹配的控制服务及安全策略；
- 对应作物、地块和速度条件下的实验验证。

控制农业机械具有现实安全风险。当前代码应视为研究原型，不应在缺少急停、限幅、通信超时保护和现场验证的情况下直接控制生产设备。
